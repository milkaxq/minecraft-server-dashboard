# Blockyard: first tester recruitment

Prepared 17 October 2026. Status: ready to post; no outreach sent and no testers recruited.

## First pilot

Recruit 3–5 Minecraft Java players for one 30-minute session on a disposable shared
world. Include one beginner, one person familiar with running a server, and people
on different internet providers. Prefer testers near the VPS region, but record
country/region rather than assuming everyone will have similar latency.

Offer free access during this pilot, with no payment details or positive-review
requirement. Do not promise separate personal servers, permanent free hosting,
perfect performance, or preservation of test worlds. Capacity must be checked
before provisioning anything additional. Keep payments disabled and registration
invite-only.

## Onboarding

1. Check current node capacity and backups. Keep the existing personal world out
   of destructive tests; prepare a separate disposable world through normal tools.
2. For dashboard testers, create individual email-bound invitations in
   **Admin → Invitations**. Share links privately; never publish invitation tokens.
3. Add registered dashboard testers as server members separately. Begin with
   MODERATOR for start/restart and console testing. Grant ADMIN only to a selected,
   trusted tester who needs files/settings/plugins/backups on the disposable server.
   Never grant platform administrator access. The owner handles membership/EULA.
4. Give gameplay-only testers the player setup/invitation link. Match the actual
   Minecraft version and required client mods; don't promise automatic installation
   by an unsupported launcher.
5. Agree a session time and a way to report problems. Explain that the test world
   can be reset and may not be kept. Remove temporary access when the pilot ends.

## Thirty-minute session

- **First 10 minutes:** join without coaching first; note where someone gets stuck.
  Dashboard testers register, verify email and locate the shared server.
- **Next 10 minutes:** play together, explore, break blocks and interact with mobs.
  Record player count and perceived lag. Profile only when diagnosing a problem.
- **Last 10 minutes:** one dashboard tester changes a harmless game setting and
  creates a backup. Only the host coordinates stop/start and any restore on the
  disposable world. Gameplay testers reconnect and confirm the expected result.
- Everyone answers: What was confusing? What broke? Would you use this again?
  Registered testers use **Feedback**; gameplay-only testers reply in the agreed
  community channel or private thread. Don't collect passwords or private tokens.

## Track results privately

Track community, moderator permission, contacted date, volunteer response, region,
ISP type if volunteered, Minecraft/loader version, role, invitation sent, join result,
issue references and follow-up. Keep emails, invitation links, player IPs and report
contents out of this repository. No recruitment responses are recorded here yet.

Success means three people can join, a beginner can find the relevant controls,
one selected tester can complete a backup safely, and all failures have a concrete
report. Expand the cohort only after reviewing those results.
